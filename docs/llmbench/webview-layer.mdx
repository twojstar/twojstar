LlmBench hosts provider services inside WebViews on Android. Because every AI provider is a heavy single-page application (SPA), LlmBench must balance persistence (keeping you signed in) with performance (not keeping every SPA alive forever). This page explains how the WebView host works and how LlmBench keeps your credentials secure.

## LRU WebView pool

Account sessions persist so you do not have to log in repeatedly. To manage memory, the Android host uses a small LRU (Least Recently Used) pool:

<Steps>
  <Step title="Active WebViews stay alive">
    The WebView for the provider you are currently using remains active and fully loaded.
  </Step>
  <Step title="Inactive WebViews are paused">
    When you switch to another provider, the previous WebView is paused to free resources while preserving session state.
  </Step>
  <Step title="Eviction under memory pressure">
    If the system runs low on memory, inactive WebViews are evicted from the pool. Cookies and session state remain provider-owned, so you stay signed in when the WebView is recreated.
  </Step>
</Steps>

This approach keeps long chats responsive without sacrificing the ability to switch between providers quickly.

## Security and authentication boundaries

<Warning>
  LlmBench must **never** scrape passwords, session cookies, OAuth tokens, or any other login credentials.
</Warning>

Authentication remains strictly between the embedded provider page and that provider. LlmBench does not intercept or store credentials. The WebView acts as a rendering container, not an authentication proxy.

## Userscript and CSS adapter layer

Provider web pages are built for desktop browsers. LlmBench includes a small, auditable adapter layer that applies userscripts and CSS to:

- Fix mobile layout issues
- Reduce wasted chrome and animations
- Handle provider-specific navigation quirks

<Note>
  These tweaks are visible and reviewable. LlmBench plans to expose a provider-tweak/userscript interface so the community can maintain adapters without modifying core app code.
</Note>

## HTTP/1.0 compatibility

The WebView layer operates over standard HTTP/S as provided by the Android WebView component. LlmBench does not add custom protocol handling beyond what the platform WebView supports natively.
